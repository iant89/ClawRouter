# Audit, 2026-11-17

The owner asked for "a full audit on ClawRouter: test the security, and that if it says it
does something, it actually does it". This page reports what was tested, how, what was found,
and what was fixed. The [security review](security.md) from phase 15 is the standing design
document; this audit tested it from the outside.

## How it was tested

- **A production build**, run as a real server (`CLAWROUTER_ENV=production`, plain HTTP on
  127.0.0.1) with a fresh database, a secret-key file and the mock providers
  (`tests/support/mock-providers.ts`) as the only upstream. No real provider was called.
- **Black-box probes**: scripts that used only HTTP, WebSocket and the command-line tools, as
  an attacker or an operator would. About 120 checks, each written down as the claim it tests
  (from the README, `docs/security.md` and the area pages).
- **A browser** (Playwright, Chromium) for HTML injection in the console.
- **Static checks**: `bun run scan-secrets --history` (every commit) and `bun audit`: both clean.
- After the fixes, the full suite (`bun run check`, 724 tests) and the failed live checks were
  run again on a rebuilt production bundle: all pass.

## Findings

| # | Severity | Finding | Status |
|---|---|---|---|
| 1 | **Medium** | **Active sessions ended when the idle timeout was short.** A session's last activity was written at most once a minute, but the idle timeout can be set to 1 minute. With that setting every console session ended one minute after sign-in, however busy; at any setting sessions could end up to a minute early. | **Fixed**: activity is now recorded at least four times per idle period (`auth-service.ts`). Unit test, and checked live: an idle session ends, an active one stays. |
| 2 | Low | **Two spellings of cloud metadata hosts passed the endpoint check**: `https://[::ffff:a9fe:a9fe]/` (169.254.169.254 as an IPv4-mapped IPv6 address) and `https://metadata.google.internal./` (trailing dot). Real impact was small: metadata services speak plain HTTP, and plain HTTP is only allowed for local hosts. | **Fixed**: hosts are compared lower case, without trailing dots, with IPv4-mapped addresses as IPv4 (`endpoint.ts`). Tests for both, plus decimal, hex and octal forms (already refused). |
| 3 | Low | **Provider captures marked whole bodies as truncated** when they held an emoji or accented letter: the size was counted in bytes, the kept text in characters. A developer reading an export would think part of the request was missing. The provider-side request body was cut by characters while its limit is in bytes. | **Fixed**: both count bytes, and a cut never splits a character (`capture.ts`, `tap.ts`). Test with emoji and accents. |
| 4 | Low | **Oversized bodies answered 400** ("Request body is too large") instead of **413**, so a client could not tell "too big" from "malformed". | **Fixed**: new error code `PAYLOAD_TOO_LARGE` (413); on `/v1` it stays in the OpenAI format (`invalid_request_error`, code `payload_too_large`). |
| 5 | Docs | `docs/rate-limits.md` said limits apply to all of `/v1/*`. `GET /v1/models` is not counted (it only lists models); the invalid-key block does apply there. | **Docs corrected.** Chat, `/v1/responses` and embeddings were each checked to count. |
| 6 | Docs | `docs/security.md` said every unsafe request needs the `x-clawrouter-csrf` header. By design only requests with a session cookie need it; every unsafe request must still be same-origin and JSON, so setup and sign-in cannot be forged cross-site. | **Docs corrected.** |

Nothing was found that lets someone in without credentials, read another user's data, gain
permissions, or read a secret.

## What was verified

**HTTP surface.** The console has a strict CSP (scripts same-origin only; no inline or eval),
`X-Frame-Options: DENY` and `frame-ancestors 'none'`, `nosniff`, a referrer policy, no HSTS on
plain HTTP, no server banner; API answers have a deny-all CSP; error answers keep the headers.
Eleven path-traversal and file probes (`..%2f`, `%2e%2e`, backslashes, `/main.js`, the CLI
bundles, `.env`, `package.json`, the secret key) served nothing. Source maps are not served.

**Setup.** A fresh install reports that setup is needed; a wrong token is refused (401); the
right token creates the administrator once, and setup then answers 409 for good.

**Sign-in and sessions.** Unknown user and wrong password get the same message, and similar
timing. The session cookie is `HttpOnly`, `SameSite=Strict`, `Path=/`, with a 256-bit token;
a pre-set cookie is replaced at sign-in (no fixation); a forged cookie is refused; a token is
dead after sign-out (server-side revocation); idle expiry works (after fix 1). Repeated wrong
passwords block the username, even with the right password afterwards (429). The password
policy refuses passwords that contain the username.

**CSRF and CORS.** A cookie request without the CSRF header, with another site's `Origin`, or
with `Sec-Fetch-Site: cross-site` is refused (403); form-encoded bodies are refused; no CORS
headers on `/api`. The WebSocket refuses a missing session and another origin.

**Authorization.** With custom roles for a user manager and a role manager: no one can make
themself Administrator, grant a role with permissions they lack, widen their own role, reset an
administrator's password, disable an administrator, or change another user's email. No other
role may hold every permission; the Administrator role cannot be edited or deleted; the last
administrator cannot disable themself. A Viewer cannot change anything, nor read logs, audit,
users or sessions. A user without roles is refused everywhere but their own pages.

**Other users' data.** A user cannot revoke another's key, see it in their list, end another's
session, see or cancel an operation without the permission, approve their own key request, or
turn someone else's request into a key (all 403/404).

**API keys and self-service.** Secrets are shown once with `Cache-Control: no-store`. A
non-administrator cannot create a key that never expires or lives over 30 days, nor set its own
rate limit; creating own keys needs `api_keys.own`; an administrator's key may never expire.
A key limited to one model cannot use another, and `/v1/models` lists only its models; a
revoked key stops at once; an expired key is refused; a disabled user's keys are suspended and
work again when the user is re-enabled. A key in the query string is not accepted.

**Secrets.** After planting a recognisable provider key, an API key secret, passwords and
temporary passwords and using the whole platform: no API answer (ten views, including
configuration export, audit and logs), no row of any of the 35 database tables, and no line of
the server log contains any of them. Captures contain no credential (`authorization` is
`[REDACTED]`). The MCP tools return no key.

**Gateway.** Chat (plain and streamed, ending in `[DONE]`), embeddings and `/v1/responses` work
end to end; errors are in the OpenAI format. Per-key limits refuse with 429 and `Retry-After`;
an address over the invalid-key limit is blocked even with a valid key; a quota of 2 requests a
day refuses the third, and switching quotas off for everyone lets it through. An alias fails
over from a dead provider to the next target, sends a failover notice, and request history
records every attempt; request history holds metadata only, not prompts or replies.

**Input.** Bodies over 64 KB (`/api`) and 25 MB (`/v1`) are refused, also when chunked without
`Content-Length`; deeply nested JSON and invalid fields are 400s; the server stays up.

**Provider endpoints (SSRF).** Cloud metadata and link-local addresses are refused, in dotted,
decimal, hex, octal, trailing-dot and IPv4-mapped forms (after fix 2); non-HTTP schemes are
refused; plain HTTP only for local hosts. Private addresses stay allowed, on purpose, for local
models. Only `providers.write` (Administrators, Operators) can set endpoints.

**MCP.** While switched off, `/v1/mcp` is a 404 with or without a key; when on, a key needs its
own MCP access; all ten tools only read.

**Client notices.** The header is ASCII-only JSON; line breaks in a message cannot inject a
header; the reply starts with the notice line; requests with tools never get text written into
them; a key's `replyNotices` switch keeps replies clean; notice lines in a conversation sent back
are removed before the provider sees them (checked in a capture of the provider call).

**Captures.** Off by default; a manual capture cannot start while off; it records the next
request; no credential is stored.

**Two-factor sign-in.** With an authenticator app enrolled the password alone gives no session;
five wrong codes burn the challenge; a code works once and is refused afterwards (no replay).

**HTML injection.** Markup in an announcement, a role name and a key name is shown as text on
the Announcements, Roles, API Access and Audit pages; nothing runs (React escapes, and the CSP
blocks inline scripts).

**Operations.** `backup` while running; `backup --list`; `doctor` (also warns when the key file
is readable by others); `migrate --status`; `restore` refuses while the server runs and refuses
a backup the configured key cannot open; `restore` into a copy; `rotate-secret-key` re-encrypts
every secret, after which the old key opens none; a server on the restored, re-keyed copy
accepts the administrator, has every user, and its provider key still authenticates at the
provider; `reset-password` prints a temporary password that must be changed before anything
else. Shutdown drains (`shutdown requested` → `draining` → `stopped`). Configuration export holds
no secret and re-imports as "unchanged". Sign-in failures, users, roles, keys, providers and
settings changes all reach the audit log.

## Remaining risks (unchanged, or newly noted)

- **DNS-based endpoints.** The endpoint check looks at the host name, not where it resolves: a
  name that resolves to a metadata address is not caught. Plain HTTP is only allowed for local
  hosts and metadata services do not speak HTTPS, which keeps this theoretical; resolving and
  checking the address at connection time would close it.
- The accepted risks in [security](security.md#residual-risks-accepted-for-now) still hold
  (username lockout, inline styles, per-process counters, provider adapters untested against
  the real OpenAI and Anthropic APIs).
- Not tested here: real TLS (HTTPS, HSTS, `Secure` and `__Host-` cookies), a reverse proxy with
  trusted-proxy headers, and SMTP against a real mail server. Unit tests cover them; see the
  MEMORY warnings.
